## 3. Действия пользователя (без автоматизации помощником)

1. Проверьте наличие чистого/зафиксированного рабочего дерева и самостоятельно создайте точку возврата до миграции (ветка/тег/коммит). Ни один файл `.owle` пока не переименовывать в `V2`.
2. Разверните **только документацию** из ZIP в корень репозитория. Корневые три Markdown заменяются новыми версиями, в которых старый текст **сохранён как архив**.
3. Переместите исходные PDF/DOCX и чужие примеры по таблице с сохранением имён и содержимого. Для Git можно использовать `git mv` индивидуально; если переносите в проводнике, проверьте результат `git status`.
4. Старые рабочие `.owle` переместите в `archive/programs/2026-11-11/` и **не открывайте их как новую рабочую V2**. Пара `T35_FIX` — историческое состояние до исправления T35.
5. Четыре autosave: локально проверьте наличие уникальной FBD/состояния, только затем решите хранение/исключение. `.gitignore` не исключает уже отслеживаемые файлы автоматически.
6. Проверьте, что `ТЗ ред. 6 ПРОЕКТ` и `СДУО-СС-01 ред. 1` остаются неизменными. Запросите/согласуйте ред. 2 структурной схемы отдельно, не создавайте фиктивную.
7. Сравните `git status`, при необходимости `git diff --stat`, историю `git log`; убедитесь, что нет удалённых без решения файлов, случайных `_autosave` и несуществующей рабочей V2. Commit/push выполняете **только вы**.
8. В новом чате передайте `AI_HANDOFF.md`, `README.md` и при необходимости `PROJECT_STATUS.md` §§19–21.
