# Режимы и переходы ПР103 V2

**V2-A УТВЕРЖДЕНА ДЛЯ SIM_ONLY 12.11.2026 / NOT IMPLEMENTED / NOT TESTED.** Этот документ — спецификация для новой FBD, не описание текущей реализации. Источники: ТЗ ред. 6, §§3.1–3.12; `PROJECT_STATUS.md` §§18–20. Утверждать разрешения на восстановление питания только после оценки риска.

## 1. Разделение понятий

| Понятие | Значение |
|---|---|
| `SB1_STOP_VALUE` | 0/1 из принятого сообщения, может быть старым |
| `KPP_MODBUS_OK` | Статус устройства по штатному Master; **не** достаточное доказательство свежести |
| `SB1_DATA_VALID` | Результат выбранной проверки последовательности/возраста/целостности; критерий пока OPEN |
| `KPP_SB1_FRESH_CONFIRMED` | Строгая свежесть для снятия защиты; в текущем `.owle` **не формируется** |
| `STOP_REQUEST` | Абстрактный логический запрос отключения, **не Q и не факт размыкания K1** |
| `RELEASE_PERMISSION` | Независимое разрешение снятия соответствующей команды/lock, **не автоматический пуск** |
| `MODE` | Одно из состояний ниже; не представлять как несколько несогласованных SR |

## 2. Режимы (УТВЕРЖДЕНО ПОВЕДЕНИЕ ДЛЯ SIM)

| MODE | Назначение | Условия команды новой системы | Условия выхода |
|---|---|---|---|
| `INIT_UNTRUSTED` | Старт/рестарт ПР103, доверие и старые разрешения сброшены | Логический STOP=1, никакого REMOTE по Modbus OK/старому STOP=0 | REMOTE лишь после отдельно доказанного доверия; D-01/D-04 OPEN |
| `REMOTE` | Нормальная непрерывно доверенная связь и LOCK=0 | SB1=1 → STOP=1; текущая SB1=0 → STOP=0 только при действительных данных | Потеря доверия → LOSS_LOCK, STOP=1 |
| `LOSS_LOCK` | Недостоверность/обрыв в REMOTE или RECOVERY_WAIT | STOP=1; самовозврата по связи нет | Только новое нажатие SB3 после отпускания и санкции персонала → LOCAL |
| `LOCAL` | Санкционированное местное управление | Временно может подавлять **старые** STOP/LOSS_LOCK, но новая достоверная SB1=1 → STOP=1 с фиксацией до отдельной санкции; SB2 независима | После ремонта LOCAL сохраняется; отдельное новое нажатие SB3 при пригодной связи → запрос RECOVERY_WAIT |
| `RECOVERY_WAIT` | Только новый запрос из LOCAL (второе нажатие SB3) при восстановленной связи | Не сбрасывать STOP/LOCK по старому STOP=0/HB/Modbus OK | Текущая достоверная SB1=0 и выполненные проверки → REMOTE; SB1=1/неудача/обрыв → LOSS_LOCK и STOP=1 |

`INIT_UNTRUSTED` принят как пятый логический режим V2-A для SIM_ONLY. Он запрещает ложное разрешение на первом цикле после старта. Конкретный способ программирования FBD ещё не выбран и не испытан; поведение режима и запрет автоматического снятия STOP остаются обязательными.

## 3. Таблица событий и приоритетов (УТВЕРЖДЕНО ДЛЯ SIM)

| Исходное состояние | Событие | Целевая реакция/запрет | Статус |
|---|---|---|---|
| REMOTE | SB1=1, данные действительны | Сформировать STOP_REQUEST | Требование ТЗ |
| REMOTE | SB1=0, связь непрерывно доверена, lock нет | Отпустить штатную команду SB1 | Требование ТЗ; критерий свежести OPEN |
| REMOTE | Потеря Modbus или достоверности | LOSS_LOCK и защитный STOP_REQUEST | Требование ТЗ |
| LOSS_LOCK | Просто возвращается Modbus_OK / HB | Сохранить lock | Требование, T35 FAIL-SIM в прежней FBD |
| LOSS_LOCK | Ответственное новое действие SB3 после проверки условий | Допуск к LOCAL | Требование ТЗ; условия/формирование фронта OPEN |
| LOCAL | SB3 удерживается после старта ПР103 | Не разрешать восстановление | Требование ТЗ |
| LOCAL | Старый STOP=0 + новый HB | Не выходить из LOCAL и не сбрасывать lock | T35 отрицательный критерий |
| LOCAL | Связь восстановлена, даже при актуальной SB1=0, **новой санкции нет** | **LOCAL сохраняется; RECOVERY_WAIT запрещён** | D-02 APPROVED / BEHAVIOR ONLY |
| LOCAL | После отпускания SB3 поступило **второе новое нажатие**, связь восстановлена | Запрос RECOVERY_WAIT; проверить актуальную SB1 | D-03 APPROVED FOR SIM; D-01/D-04 OPEN |
| LOCAL | Новая достоверная SB1=1 | STOP=1 фиксируется; LOCAL не отменяет новый STOP; SB1=0 не сбрасывает его автоматически | D-15 APPROVED FOR SIM; истинная свежесть D-01/D-04 OPEN |
| RECOVERY_WAIT | Достоверная SB1=1, повторный обрыв или провал проверки | LOSS_LOCK, STOP=1, старая санкция недействительна | D-15 APPROVED FOR SIM |
| RECOVERY_WAIT | Вторая санкция уже поступила, связь устойчива, SB1=0 действительно актуальна | Возможен REMOTE после всех проверок | V2-A SIM; доказательство свежести D-01/D-04 OPEN |
| Любой | Неизвестная свежесть/рестарт | Снять автоматические разрешения; не считать старые ACK новыми | Требование безопасности, механизм детектирования OPEN |

### 3.1. Историческая стадия D-02 до утверждения V2-A (текст сохранён)

**D-02 согласовано (поведение):** после ремонта оптики ПР103 **остаётся в разрешённом LOCAL**, пока персонал не совершит **новое сознательное действие**, а перед выходом не будет проверено актуальное состояние SB1. Modbus OK, новый HB и старый STOP=0 не выводят из LOCAL и не очищают LOCK. Повторное нажатие SB3 — пока инженерное предложение (D-03 OPEN); свежесть SB1, рестарты и replay (D-01/D-04), времена и реакция на SB1=1 (D-13–D-15) также OPEN.

**Источник ОВЕН:** «Owen Logic (версия 3.3). Руководство пользователя», версия 2.12, 09.2026; `references/owen/manuals/rp_owen_logic.pdf`; §4.5 стр. 59–62 (SIM), §5.3.2 стр. 111–113 и §5.3.2.1 стр. 121–123 (Modbus Master), §7.2.1 стр. 163–165 (RS/SR/RTRIG/FTRIG), §7.2.2.2 стр. 167–168 (TON). Детали: `docs/reference/OWEN_LOGIC_SOURCE_AUDIT.md`.

### 3.2. Утверждённая V2-A логика и её пределы

**УТВЕРЖДЕНО 12.11.2026 — V2-A / SIM_ONLY:** ПР205 передаёт SB1; ПР103 использует пять состояний `INIT_UNTRUSTED`, `REMOTE`, `LOSS_LOCK`, `LOCAL`, `RECOVERY_WAIT` и раздельные `STOP_REQUEST`/`RELEASE_PERMISSION`. Существующая SB3 используется для **двух отдельных новых нажатий**: вход в LOCAL из LOSS_LOCK и запрос возврата из LOCAL после ремонта оптики. Между нажатиями обязательно отпускание; удержание при запуске не считается новым действием. Восстановление Modbus/HB/старого STOP=0 само не выводит из LOCAL. Подтверждённая **текущая** SB1=1 имеет приоритет STOP даже в LOCAL; STOP не снимается последующей SB1=0 без разрешённого перехода. При неудаче проверки или повторном обрыве во время RECOVERY_WAIT → LOSS_LOCK, STOP=1; возврат в REMOTE лишь после санкции персонала и подтверждения SB1=0.

**Граница утверждения:** `APPROVED FOR SIM DESIGN / NOT IMPLEMENTED / NOT TESTED / HW NOT APPROVED`. **D-01/D-04 OPEN:** действительная свежесть SB1 при незамеченных рестартах, replay/wrap/старых данных не доказана; HB и Modbus status недостаточны. Для SIM автомата допускаются *искусственно заданные* валидные входы, но не утверждение реального обмена. Времена D-13/D-14, МЭ210 D-09, аппаратные D-05–D-12 OPEN. ТЗ ред. 6 — ПРОЕКТ. Физические Q/K1/SB2/ЩАО/МЭ210 не трогать; новых `.owle` и PASS-SIM V2 нет; T35/P04-02 остаются FAIL-SIM.

В тестах автомата можно **вручную** задавать `COMM_OK_SIM`, `SB1_VALID_SIM`, `SB1_STOP_SIM`; это не результат реальной Modbus-операции. До согласования времён и испытаний запрет считать удержание SB3 при boot новым фронтом и засчитывать одно нажатие дважды. См. SIM-план `V2-MODE-01…11`.

## 4. Требования к SB3

- SB3 — санкционированное **местное** управление при неисправной оптике, не универсальный reset аварий.
- Новое нажатие должно быть отличимо от удерживания до старта. Возможная схема FBD `SB3_seen_released_after_boot` + фронт — **гипотеза реализации**, проверяется отдельно (обычный RTRIG может выдать импульс на первом цикле, если SB3 уже 1).
- До входа в LOCAL персонал должен координироваться с КПП и исключить опасный повторный пуск; программа не может заменить эту процедуру.
- Ранее доставленная SB1=1 при отсутствии канала не должна навечно блокировать *санкционированный* LOCAL, иначе не выполнено ТЗ §3.6.
- При достоверном возвращении связи и свежей SB1=1 команда отключения снова становится приоритетной по ТЗ §3.9.

## 5. Безопасные инварианты для любых FBD

1. Никакое одиночное `MODBUS_OK`, HB или `STOP=0` не является `RESET(LOCAL)`/`RESET(LOCK)`.
2. Измеренная индикация трёх фаз никогда не заменяется состоянием команды STOP, К1 или абстрактным `STOP_REQUEST`.
3. При выходе из LOCAL требуется явная процедура; даже подтверждённая SB1=0 не равна разрешению пуска.
4. После рестарта недостоверные и удержанные до рестарта разрешения не становятся новыми действиями персонала.
5. Физическое соответствие `STOP_REQUEST` -> размыкание K1 НЕ утверждать до рабочего электрического проекта.

## 6. Предлагаемые диагностические переменные (имена рабочие)

`V2_MODE`, `V2_INIT_UNTRUSTED`, `V2_COMM_DEVICE_OK`, `V2_FRAME_UPDATED`, `V2_SB1_DATA_VALID`, `V2_STOP_REQUEST`, `V2_RELEASE_PERMISSION`, `V2_LOCAL_AUTH_EDGE`, `V2_RETURN_AUTH_EDGE`, `V2_RECOVERY_WAIT`, `V2_LOCKED_BY_COMM_LOSS`.

Создавать их после согласования формул/переходов, не автоматически. В Owen Logic диагностический участок должен участвовать в расчёте сетевого диагностического выхода для корректного SIM-наблюдения; не подключать его ради наблюдения к физическим Q/K1.
