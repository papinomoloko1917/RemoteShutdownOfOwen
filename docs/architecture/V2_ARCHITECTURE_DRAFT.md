# Архитектура RemoteShutdownOfOwen V2 — проект на согласование

**АКТУАЛИЗАЦИЯ 13.11.2026 — V2-A реализована только как первый локальный ST/FBD Unit-SIM автомат ПР103; ПР205/Modbus/HW не реализованы в V2.** Наблюдались базовая цепочка пяти состояний и целевые отрицательные N-01…N-03; остались незавершённые N-04b/N-05b, D-01/D-04 OPEN. Отчёт `docs/testing/V2_SIM_RESULTS_2026-11-13.md`, `PROJECT_STATUS.md` §25. Не путать частичную симуляцию с утверждённой к эксплуатации реализацией. Источник требований — ТЗ ред. 6 (ПРОЕКТ), §§3.1–3.12 и 5.1–5.5; проектные детали ниже сохраняют статус ПРЕДЛОЖЕНИЕ, где не утверждены отдельно.

## 1. Границы оборудования

- КПП: SB1 — штатная дистанционная кнопка; HL1 — индикация на ПУО.
- ЩАОП1: **ПР205-24.1211.02.0.0**; КСН210-2.1 (Ethernet + SFP), резервированное 24 В питание по проекту; HL2/HL3/HL4 на щите.
- Связь: существующая оптика ~600 м, два КСН210-2.1; КСН — **неуправляемый Layer 2**, не источник подтверждения достоверности SB1.
- ЩАОП2: **ПР103-24.1610.03.1.0**, SB3, потенциальное реле K1, модуль измерения МЭ210-701 (физически ещё не испытан).
- Действующий ЩАО/АВР/ДГУ: собственный алгоритм **не изменяется**. SB2 — независимая штатная кнопка разрыва существующей цепи. Новая система не должна шунтировать SB2.

## 2. Функциональные слои

```text
[ПР205] Физический SB1 + фильтрация -> команда и диагностический кадр
                            |
                     Modbus TCP Slave
                            |
                  КСН210 — оптика — КСН210
                            |
                     Modbus TCP Master
                            |
[ПР103]  1. Статус устройства + валидность данных / тайм-аут
         2. Установление режима REMOTE / LOSS_LOCK / LOCAL / RECOVERY_WAIT
         3. Состояние SB1 и защитная команда STOP_REQUEST (логическая)
         4. Отдельный RELEASE_PERMISSION (только в разрешённых сценариях)
                            |
                  K1: ФИЗИЧЕСКАЯ ЧАСТЬ НЕ ПРОЕКТИРОВАНА
```

Никакая диагностика по одному пакету не доказывает отсутствие опасного отказа. `ModbusOK`, `DATA_VALID`, `STOP=0`, `RELEASE_PERMISSION` и `MODE` — **разные** сигналы.

## 3. Стратегия реализации (ПРЕДЛОЖЕНИЕ)

### ПР205

- Физическая SB1 -> фильтр -> один согласованный выходной сетевой снимок команды.
- Использование уже изученного диагностического кадра `SB1_FRAME_TX = 2×HB+STOP` (DEC 16389) допустимо **как диагностика**, не как математическое доказательство свежести после restart/wrap.
- Контроллер не должен сам управлять K1/LOCAL/ЩАО; не добавлять фиктивные связи к Q для симуляции.
- Экспериментальные `KPP_CHALLENGE_RX` 16390 и `SB1_ACK_FRAME_TX` 16391 сохранить только в историческом V1. Никакого автоматического переноса этих цепей в новую FBD без отдельного решения.

### ПР103

- Использовать `Статус` Master для `KPP_MODBUS_OK`, а не самодельный TCP watchdog. Фактически такой статус уже имеется в старой FBD.
- Отдельно контролировать срок/монотонность/валидность кадра SB1. Положительный heartbeat без независимого подтверждения не снимает lock/LOCAL.
- Состояния `REMOTE`, `LOSS_LOCK`, `LOCAL`, `RECOVERY_WAIT` определить единой таблицей, а не разрозненными reset SR/TON. См. `OPERATING_MODES_V2.md`.
- Разнести вычисления `STOP_REQUEST`, `RELEASE_PERMISSION`, `DISPLAY_STATUS` и `VOLTAGE_ABSENCE_CONFIRMED`.
- Физическую карту Q/NO/NC/K1 не задавать до утверждённой электрической схемы и оценки опасных отказов.

### МЭ210-701 — отдельный измерительный Slave для ПР103 (дополнение 12.11.2026, ПРЕДЛОЖЕНИЕ)

- Источник фактов: `references/owen/manuals/re_me210-701.pdf` v1.41, §6.5.1 и табл. 6.5, стр. 28–31; диагностика §6.6.10, стр. 45; полный аудит — `docs/reference/ME210_701_OWEN_SOURCE_AUDIT.md`.
- ПР103 предполагается настроить как Modbus TCP Master **к двум разным Slave**: `PR205_KPP` для SB1 и отдельному `ME210` для фазных измерений. **Настройки ещё не созданы**, фактический IP МЭ210 неизвестен.
- Предлагаемые запросы `ME210`: FC03 **5240 / 6 регистров** (FLOAT32 A/B/C) и FC03 **5340 / 2 регистра** (UINT32 диагностика). Проверить размеры данных и порядок регистров при настройке Owen Logic.
- Логически развести `ME210_COMM_OK`, `ME210_DATA_VALID`, `THREE_PHASES_LOW`. При недостоверных измерениях состояние **UNKNOWN**, а не «0 В»; параметры порогов и времён `OPEN`. Не использовать MЭ210 как средство сертифицированной проверки отсутствия опасного напряжения.
- Результат измерения для HL2 требует подтверждения точки установки относительно АВР/ДГУ и ограниченной формулировки «технологический критерий достигнут». **Нет права изменять алгоритмы STOP/LOCAL/RELEASE** на основании новых измерений без отдельного согласования.

## 4. Два режима требований к свежести

**Путь A, ВЫБРАН ДЛЯ V2-A SIM (не доказывает реальную свежесть):** исключить автоматический сброс аварийных блокировок после нарушений, рестартов и LOCAL; снятие требует специальной согласованной процедуры. Штатная связь+heartbeat может служить ограниченным диагностическим признаком в непрерывном REMOTE, однако сама не исключает незамеченного рестарта и повтора. Строгая гарантия `STOP=0` при небезопасных последствиях не может опираться только на HB.

**Путь B, не выбран для V2-A SIM; возможный будущий вариант при необходимости реальной гарантийной свежести:** отдельный протокол подтверждения свежести с защищённой от повтора сессией/эпохой обоих ПР; программно проверить в SIM, аппаратно на изолированном стенде; энергонезависимость/переполнение/сетевые задержки должны быть доказаны. P03/P04-01 не доказывают Путь B; P04-02 обнаружил отказ.

**Ни один путь не является утверждённой функцией функциональной безопасности.** Выбор пути и допустимость переходов должны быть согласованы до программирования разрешений, особенно учитывая потенциальное автоматическое восстановление питания по алгоритму ЩАО.

## 5. Отношение к примерам ОВЕН

Пример `2 ввода на общую шину.owle` (Owen Logic 2.7.350; иная модификация ПР205) демонстрирует разделение команд/состояний, фильтрацию входов, выдержки, взаимные запреты. **Не** является готовой программой дистанционной SB1/SB3.

`Counter.owl` и `description_counter.docx` — учебный пример счётчиков CT/CTN/CTU для ПР200/старой версии Owen Logic. Счётчик пригоден для диагностики, **не** гарантирует уникальность запросов после reboot. Не вставлять проект целиком.

## 6. Условия запрещённых переходов

- `LOCAL=1` + старое `STOP=0` + изменился HB/`MODBUS_OK=1` -> **НЕЛЬЗЯ** выходить из LOCAL / сбрасывать lock.
- Запуск/рестарт ПР103 или ПР205 -> **НЕЛЬЗЯ** считать старый `STOP=0` новым разрешением.
- Потеря связи -> защитный запрос отключения, кроме санкционированного LOCAL по процедуре.
- Удержанная при включении питания SB3 -> **НЕ** новый сознательный запрос местного разрешения.
- `VOLTAGE_ABSENCE_CONFIRMED` -> только реальные достоверные измерения **всех трёх фаз** МЭ210, не из STOP/K1.

## Обновление D-02 — 12.11.2026

**D-02 согласовано (поведение):** после ремонта оптики ПР103 **остаётся в разрешённом LOCAL**, пока персонал не совершит **новое сознательное действие**, а перед выходом не будет проверено актуальное состояние SB1. Modbus OK, новый HB и старый STOP=0 не выводят из LOCAL и не очищают LOCK. Повторное нажатие SB3 — пока инженерное предложение (D-03 OPEN); свежесть SB1, рестарты и replay (D-01/D-04), времена и реакция на SB1=1 (D-13–D-15) также OPEN.

Из LOCAL нельзя автоматически переходить в RECOVERY_WAIT при одном восстановлении связи; источник нового действия (предлагаемая повторная SB3) остаётся D-03 OPEN. **Источник ОВЕН:** «Owen Logic (версия 3.3). Руководство пользователя», версия 2.12, 09.2026; `references/owen/manuals/rp_owen_logic.pdf`; §4.5 стр. 59–62 (SIM), §5.3.2 стр. 111–113 и §5.3.2.1 стр. 121–123 (Modbus Master), §7.2.1 стр. 163–165 (RS/SR/RTRIG/FTRIG), §7.2.2.2 стр. 167–168 (TON). ## 9. Утверждение V2-A / SIM_ONLY (12.11.2026)

**УТВЕРЖДЕНО 12.11.2026 — V2-A / SIM_ONLY:** ПР205 передаёт SB1; ПР103 использует пять состояний `INIT_UNTRUSTED`, `REMOTE`, `LOSS_LOCK`, `LOCAL`, `RECOVERY_WAIT` и раздельные `STOP_REQUEST`/`RELEASE_PERMISSION`. Существующая SB3 используется для **двух отдельных новых нажатий**: вход в LOCAL из LOSS_LOCK и запрос возврата из LOCAL после ремонта оптики. Между нажатиями обязательно отпускание; удержание при запуске не считается новым действием. Восстановление Modbus/HB/старого STOP=0 само не выводит из LOCAL. Подтверждённая **текущая** SB1=1 имеет приоритет STOP даже в LOCAL; STOP не снимается последующей SB1=0 без разрешённого перехода. При неудаче проверки или повторном обрыве во время RECOVERY_WAIT → LOSS_LOCK, STOP=1; возврат в REMOTE лишь после санкции персонала и подтверждения SB1=0.

**Граница утверждения:** `APPROVED FOR SIM DESIGN / NOT IMPLEMENTED / NOT TESTED / HW NOT APPROVED`. **D-01/D-04 OPEN:** действительная свежесть SB1 при незамеченных рестартах, replay/wrap/старых данных не доказана; HB и Modbus status недостаточны. Для SIM автомата допускаются *искусственно заданные* валидные входы, но не утверждение реального обмена. Времена D-13/D-14, МЭ210 D-09, аппаратные D-05–D-12 OPEN. ТЗ ред. 6 — ПРОЕКТ. Физические Q/K1/SB2/ЩАО/МЭ210 не трогать; новых `.owle` и PASS-SIM V2 нет; T35/P04-02 остаются FAIL-SIM.
