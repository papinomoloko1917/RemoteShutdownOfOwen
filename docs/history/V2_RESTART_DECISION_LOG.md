# Решение о новом старте реализации V2 — 11.11.2026

**Статус:** принято решение готовить новую архитектуру и набор документов; **сама FBD V2 не начата**, контрольные точки V1/Т35 сохраняются. GitHub изменяет и публикует только пользователь.

## Причины

1. В V1 после серии диагностических улучшений не устранён дефект T35 — автоматический возврат из LOCAL/сброс link-loss lock при старом STOP=0.
2. P03 и P04-01 подтвердили корректную локальную арифметику/удержание ACK, но P04-02 воспроизвёл повторное принятие N=4 после restart.
3. Дополнительные Sel/Div/GT/diagnostics усложнили FBD, а единого утверждённого автомата состояний нет.
4. Приложенные РЭ ОВЕН подтвердили штатные средства Modbus Master/Slave, статус устройств и механизм опроса; образец АВР показал более понятное разделение команд и разрешений.
5. Полный перезапуск проекта как предприятия не требуется: неизменными остаются требования ТЗ, ограничения безопасности, накопленные отрицательные результаты, описания физического объекта и решение не управлять действующим ЩАО без утверждённой схемы.

## Статус существующих идей

| Идея | Результат |
|---|---|
| `SB1_FRAME_TX = 2×HB+STOP` (16389) | Полезная диагностика, не строгая freshness |
| Challenge/ACK DEC 16390/16391 | Исторический P01–P04, сохранить в архиве, не переносить автоматически |
| Эпоха с Retain | Исследовательское предложение, не протестировано как гарантия; CR2032 — ограничение |
| `P05_EPOCH_PROBE` DEC 16392/16393 | Предложено в старом чате, **не создано и не испытано** |
| Переработка FBD ПР103 `REMOTE_RETURN_STABLE` | Направление исследования, **не выполненная правка** |
| Новый протокол свежести | Отложен до утверждения требований к автоматическому восстановлению и модели угроз |
| Новый автомат режимов и запрет авто-выхода из LOCAL | Проект V2, **подлежит согласованию** |

## Решение по содержимому репозитория

- Историю `PROJECT_STATUS.md` §§1–20 и checkpoint сохранит последующая редакция §21; без «очистки» прошлых FAIL.
- Справочные материалы производителя и примеры помещаются в отдельные директории, не смешиваются с рабочими `.owle`.
- Активные V2 `.owle` появляются только после утверждения архитектуры; старые физически остаются в `archive/`.
- `*_autosave.owle` перед удалением/исключением сравниваются пользователем: в Git они сейчас отдельные blob, **не** считать идентичными main-файлам.
- Никаких физических подключений, записи на реальные реле или Git push со стороны помощника.

## Точка продолжения

**Сначала** согласовать таблицу режимов `OPERATING_MODES_V2.md` и решения D-01–D-04 `SAFETY_AND_OPEN_DECISIONS.md`; только **затем** создание двух новых `.owle` по крупным функциональным узлам.
