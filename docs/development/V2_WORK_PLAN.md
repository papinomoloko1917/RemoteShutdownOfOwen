# План новой реализации V2 (по крупным этапам)

**STATUS: PLAN / NOT STARTED.** Принимаем «чистый лист» для кода, но не для требований и накопленных проверок. Любая новая FBD после согласования должна создаваться в **двух новых** файлах, а не путём незаметного перезаписывания архивного checkpoint. Не клонировать множество экспериментальных `.owle`.

## Этап 0. Подготовка Git / исходных данных (без изменения программ)

- [ ] Пользователь самостоятельно создаёт контрольный коммит (либо тег/ветку) со всеми нужными файлами текущего HEAD. Никто не делает `git push` из чата.
- [ ] По `FILE_MIGRATION_PLAN.md` переносит исторические `.owle` в `archive/` **с сохранением содержимого**. Autosave проверить на уникальность, при необходимости хранить только как архив, не как рабочую версию.
- [ ] Проверяет конфликт схемы ТЗ ред. 6 / СДУО ред. 1 и несовпадение EPLAN .03.2.0 с нашей .03.1.0.
- [ ] Читает `AI_HANDOFF.md` и просит согласовать режимы/переходы перед созданием блоков.

**Критерий готовности:** история сохранена, есть ясные источники и ещё не создано никаких новых активных `.owle`.

## Этап 1. Архитектура и таблица переходов

- [ ] Согласовать `OPERATING_MODES_V2.md` целиком; D-02 (ручной возврат LOCAL после ремонта оптики) уже согласован только по поведению, D-01/D-03/D-04/D-15 остаются OPEN.
- [ ] Выбрать стратегию достоверности: A (контролируемый выход из неопределённости) или B (полный protocol/epoch), документировать ограничения A.
- [ ] Отдельно утвердить имена/интерфейс абстрактных команд: `STOP_REQUEST`, `RELEASE_PERMISSION`, без физического Q.
- [ ] Составить таблицу источников (`SB1 физическая`, `Modbus status`, `frame`, `SB3`) и таблицу приоритетов.

**Критерий готовности:** ни одного запрещённого перехода в таблице, противоречия с ТЗ отмечены открытыми, а не решёнными предположением.

## Этап 2. ПР205 V2 — минимальный передатчик

- [ ] Один новый `programs/v2/PR205_REMOTE_V2_SIM_ONLY.owle` с целевым прибором **ПР205-24.1211.02.0.0**, штатным чтением физической SB1, фильтрацией и явной публикацией диагностического кадра.
- [ ] Заранее определить, какой регистр/тип станет канонической командой. Не переносить экспериментальный ACK 16391 автоматически.
- [ ] Тестировать только реальную ветвь FBD и диагностический сетевой выход, не Q/К1.

**Критерий готовности:** FBD-индикаторы логической команды и кадра соответствуют разработанной таблице в SIM. Это ещё не Modbus TCP на железе.

## Этап 3. ПР103 V2 — отдельные уровни Master / modes / STOP

- [ ] Один новый `programs/v2/PR103_CONTROL_V2_SIM_ONLY.owle` с прибором **ПР103-24.1610.03.1.0**.
- [ ] Использовать штатный статус Slave `PR205_KPP`. Учитывать, что это не диагностика каждой FC03.
- [ ] Проверка валидности кадра/периода — отдельная ветвь, не формирует reset LOCAL напрямую.
- [ ] Машина состояний со строго разделёнными `STOP_REQUEST` и `RELEASE_PERMISSION` (и, при необходимости, `SB1_DATA_VALID`).
- [ ] Никаких внешних Q/K1/МЭ210; все выходы только SIM-диагностика.

**Критерий готовности:** T35 отрицательный сценарий блокируется, переходы режима соблюдают таблицу; не выдавать фиктивный `FRESH=TRUE`.

## Этап 4. Только целевые SIM / регрессия

- [ ] `SIM_TEST_PLAN_V2.md`: INIT, SB3 удержана, REMOTE, обрыв без SB1, обрыв при SB1, LOCAL, возврат без автоматического reset, повтор P04-02 как негативная проверка лишь при смене алгоритма IDs.
- [ ] Результат каждого нового сценария — `PASS-SIM`, `FAIL-SIM`, `BLOCKED`, вместе с входами, ожидаемыми/наблюдаемыми выходами, версией `.owle`.
- [ ] Исторические P03/P04-01 не повторять только ради полноты списка; повторять лишь когда новая логика использует тот же механизм и результат влияет на безопасность.

## Этап 4A. МЭ210-701 как отдельная измерительная подсистема (ДОБАВЛЕНО 12.11.2026)

- [ ] Изучить `docs/reference/ME210_701_OWEN_SOURCE_AUDIT.md` и РЭ МЭ210-701 v1.41 (стр. 28–31, 45).
- [ ] Согласовать назначение HL2, три точки измерения, допустимые пороги/выдержки/фильтр и обработку `UNKNOWN` (открытое D-09).
- [ ] После согласования создать в **новой** конфигурации ПР103 отдельное устройство Master `ME210` с предложенными FC03 5240/6 и 5340/2; проверить в Owen Logic типы, порядок слов и ограничения группировки, без физических Q.
- [ ] Выполнить **только необходимые** `V2-ME-S01…S06` (сейчас `NOT RUN`) и задокументировать результат; не выдавать имитацию аналоговых входов за реальные измерения.

**Нельзя** связывать `ME210_DATA_VALID` с разрешением снятия STOP/LOCK без отдельно утверждённых требований. Определение отсутствия напряжения для допуска к работам остаётся независимой регламентной процедурой.

## Этап 5. Изолированный стенд и аппаратная часть (НЕ СЕЙЧАС)

Только отдельное согласование. Проверить настоящие FC03/FC06, перезапуски, питание КСН/SFP/ПР, потерю канала, МЭ210, а затем — при утверждённой рабочей электрической схеме — поведение K1/SB2 в безопасно изолированных условиях. Действующий ЩАО не затрагивать. SIM и стенд не автоматически равны вводу в эксплуатацию.

## Минимум сопровождения нового чата

В новом чате прикладывать/давать ссылку на `AI_HANDOFF.md`, `OPERATING_MODES_V2.md`, `MODBUS_AND_FRESHNESS.md`, на **обе** актуальные V2 `.owle` (когда появятся), а для требуемой деталей — `PROJECT_STATUS.md` §§19–21. Правки FBD согласовывать целыми функциональными узлами. Новый шаг фиксировать в журнале, не теряя старые отрицательные результаты.
