**Тип свидетельства:** просмотр результатов Owen Logic 3.3.378.0 по скриншотам в переписке, цикл SIM 100 мс. **Не** стенд, не аппаратное испытание, не проверка Modbus TCP или безопасности действующего ЩАО. Таблицы ниже — наблюдения конкретного испытания, а не аттестация всего устройства.

**Основание документа:** согласованная архитектура V2-A от 12.11.2026 (`PROJECT_STATUS.md` §24); запуск и проверки от 13.11.2026. ## 2. Соединения SIM-схемы

| Вход | Цепь FBD | Вход ST | Смысл |
|---|---|---|---|
| I1 | напрямую | `xCommOk` | синтетическая связь |
| I2 | напрямую | `xSb1Valid` | синтетическая достоверность SB1 |
| I3 | напрямую | `xSb1Stop` | синтетический STOP SB1 |
| I4 | NOT → TON (300 мс) → FTRIG | `xSb3PressEdge` | одно новое нажатие SB3 после отпускания |
| I5 | NOT → TON (300 мс) → FTRIG | `xBootAuthEdge` | отдельное событие доверия при INIT |
| I6 | RTRIG | `xFreshEdge` | **искусственный** новый фронт FRESH |
| FI1 | напрямую | `xRecoveryCheckFail` | принудительный отказ проверки |

| Выход ST | Диагностика ПР103 Slave | Адрес DEC | Кодирование |
|---|---|---:|---|
| `udiMode` | `V2_DBG_MODE` | 16402 | целочисленно 0…4 |
| `xStopRequest` | `V2_DBG_STOP` | 16403 | BOOL → SEL 0/1 |
| `xReleasePermission` | `V2_DBG_RELEASE` | 16404 | BOOL → SEL 0/1 |
| `xLockedByCommLoss` | `V2_DBG_LOCK` | 16405 | BOOL → SEL 0/1 |

**Значения режимов:** 0 = `INIT_UNTRUSTED`; 1 = `REMOTE`; 2 = `LOSS_LOCK`; 3 = `LOCAL`; 4 = `RECOVERY_WAIT`. Выдержки 300 мс — испытательные, **не** утверждённые параметры реальных SB3/BOOT (D-13/D-14 OPEN). Диагностические адреса относятся только к SIM Slave ПР103, не к ПР205.

## 3. Наблюдаемые переходы — основная последовательность

| Сценарий | Показанные результаты MODE / STOP / RELEASE / LOCK | Статус доказательства |
|---|---|---|
| INIT при недоверенных данных | `0 / 1 / 0 / 0`, связь/VALID сами по себе не разрешили выход | PASS-SIM для синтетического старта |
| Новый BOOT, затем новый FRESH | `0 → 1`; после входа REMOTE `1 / 0 / 1 / 0` при SB1_STOP=0 | PASS-SIM, но события синтетические |
| REMOTE, доверенная SB1=1 | `1 / 1 / 0 / 0` | PASS-SIM |
| Потеря I1 | `1 → 2`, `2 / 1 / 0 / 1` | PASS-SIM |
| Восстановление I1 без SB3 | остаётся `2 / 1 / 0 / 1` | PASS-SIM |
| Первое новое SB3 | `2 → 3`, наблюдалось `3 / 0 / 0 / 1` при SB1_STOP=0 | PASS-SIM |
| Удержание LOCAL без второго SB3 | остаётся `3 / 0 / 0 / 1` | PASS-SIM |
| Второе новое SB3 | `3 → 4`, `4 / 1 / 0 / 1` | PASS-SIM |
| Новый FRESH уже после входа в WAIT | `4 → 1`, `1 / 0 / 1 / 0` в основной последовательности | PASS-SIM для искусственного FRESH |

## 4. Отрицательные испытания

| ID | Фактически показано | Корректная запись статуса |
|---|---|---|
| N-01 | В LOCAL `I3: 0→1→0`: STOP стал 1 и сохранился при возврате I3=0; MODE=3, RELEASE=0, LOCK=1 | **PASS-SIM** (только синтетически достоверная SB1) |
| N-02 | В RECOVERY_WAIT `I1=0` вернуло в LOSS_LOCK, после I1=1 остались MODE=2, STOP=1, RELEASE=0, LOCK=1 | **PASS-SIM** |
| N-03 | В RECOVERY_WAIT `FI1=1` вернуло в LOSS_LOCK, снятие FI1 не сняло LOCK | **PASS-SIM** |
| N-04a | FRESH (`I6=1`), возникший ещё в LOCAL и затем удерживаемый в RECOVERY_WAIT, не дал автоматического REMOTE | **PASS-SIM — узкий критерий старого уровня I6** |
| N-04b | В конце серии после нового `I6: 0→1` на предъявленном последнем кадре MODE всё ещё отображён как 4; отдельного устойчивого скриншота MODE=1 после следующего цикла нет | **NOT VERIFIED**, не присваивать всему N-04 PASS до дополнительного подтверждения; основная последовательность `4→1` была пройдена отдельно |
| N-05a | После перезапуска SIM наблюдались INIT=0, STOP=1, RELEASE=0, LOCK=0 | **PASS-SIM — только исходное состояние** |
| N-05b | Остановка/повторный старт SIM сбрасывает принудительные состояния кнопок; пользователь не смог оставить I4=1 сквозь рестарт | **NOT TESTED / методически недоступно этим способом**; рестарт с физически удержанной SB3 не проверен |

**Методический вывод:** не объединять N-05a и N-05b. Предыдущее словесное подтверждение «N-04 PASS» было слишком широким: для последнего `I6 0→1` нужен ещё отдельный устойчивый кадр выхода в REMOTE; кратковременные отображения входов и ST-выходов могут относиться к различным фазам цикла наблюдения. Переход `4→1` при отдельном тесте основной последовательности уже наблюдался, но не заменяет N-04b.

## 6. Не закрыто и запрещено утверждать

- **D-01/D-04 OPEN:** отсутствует доказательство получения *текущей* SB1 из реального ПР205 через Modbus при reboot/replay/wrap/повторении старых регистров. Синтетическое `I2=1` и `I6` не доказывают свежести.
- **D-13/D-14 OPEN:** реальная длительность SB1, выдержки SB3, сканирование/латентность. Параметры 300 мс и 100 мс относятся только к тесту.
- **D-05–D-12 OPEN:** аппаратура, схема K1/SB2/ЩАО, прошивки, FC03/FC06, МЭ210-701. ТЗ ред. 6 — ПРОЕКТ. Нет подключения физических Q, K1, SB2, ЩАО или измерительного МЭ210.
- Исторические **T35 и P04-02 = FAIL-SIM**; они **не** переаттестованы и не «исправлены» этим unit-SIM.
- `RELEASE_PERMISSION=1` — только логическая диагностика автомата; это **не** команда включения ДГУ, питания, K1 и не подтверждение безопасного состояния.
- Профессионально утверждённая процедура входа в LOCAL, восстановление после аппаратных рестартов и влияние `xLocalStopHold` на дальнейшие сеансы требуют отдельного анализа и согласования.
